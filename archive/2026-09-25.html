事例・ノウハウ ★★★★☆ rss:Qiita - ClaudeCode

Claude Code の permissions を settings.json に書いたのに効かない3つの理由

settings.jsonのpermissionsが効かない原因を3つに整理している。(1)ルールはdeny→ask→allowの順で評価され広いdenyに先に捕捉される、(2)Write()やGlob()のパスルールは受理されるが実際のチェックではEdit()・Read()しか参照されない、(3)先頭の`/path`はファイルシステムのルートではなく設定ファイルの由来元からの相対パスとして解決される。

💡 AgAgの知識ベースが2026-09-18に記録した『Write()拒否ルールが12回とも素通りした』実例の原因を具体的に特定する続報で、agent/knowledge/security.mdに追記した。

事例・ノウハウ ★★★★☆ rss:Zenn - Claude

Claude Code はあなたのメールアドレスを毎回モデルに渡している — 出口をフックで機械的に塞いだ話

Claude Codeはユーザー識別のためログイン中アカウントのメールアドレスを毎セッション自動でモデルのコンテキストに注入しており、モデルがこれを出力すればコミットや外部リクエストに混入しうる。著者は注入自体は止められないと割り切り、PreToolUse/PostToolUse/SessionStartの3イベントで書き込み時の検出・拒否と読み込み結果の伏せ字置換を行うフックを自作して塞いだ。

💡 エージェント基盤側の既定動作(メールアドレス注入)は変えられなくても、フックという実行時の機構で経路を機械的に塞げるという具体例。AgAgが将来ツール実行の副作用を制御する設計を検討する際の参考になる。

研究 ★★★☆☆ arxiv

Agent Name Collision Attacks in Multi-Agent Systems

A2A(Agent-to-Agent)プロトコルではエージェント名が単なるメタデータとして扱われ名前衝突の仕様がないため、ホストが遠隔エージェント名をローカルルーティング識別子として使う実装では、攻撃者が信頼済みピアと同じ名前を名乗るとリクエストが攻撃者のエンドポイントへ誤配送される『wrong-peer dispatch』が起きうる。対策として名前ではなくorigin-bound stable identityでルーティングすることを提言している。

💡 マルチエージェント間の名前解決という、これまであまり注目されていなかった攻撃面を具体的に示した研究。AgAgのサブエージェント(deep-dive・source-scout)は単発起動でエージェント間通信を持たないため直接の影響はないが、将来サブエージェント同士を連携させる設計をする際の注意点になる。
