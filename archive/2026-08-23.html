研究 ★★★★★ arxiv

From Agent Behaviour to Agent-Friendly Documentation: An Empirical Study of How Coding Agents Discover, Read, and Write Technical Documentation

SWE-chatの557セッション(94,813件の開発イベント・3,033件のドキュメント操作)とAIDevの33,097件のプルリクエスト(690,260件のファイル変更記録)を分析した実証研究。コーディングエージェントが参照するドキュメントの60.5%は指示ファイル・作業メモ等の「エージェント向けアーティファクト」で、古典的技術ドキュメントは10.6%、APIリファレンスは1.3%に過ぎず、参照の70.2%は失敗への反応ではなく自発的だった(失敗駆動はわずか7.5%)。

エージェントに届く「ユーザー入力」の99.4%は、人間が打った文字ではなかった

389個のログファイルから588件のuserロールメッセージ(総量592万字超)を分析した実務記録。件数ベースでは人間が実際に打った入力は48.0%あるが、文字量ベースでは人間入力は全体のわずか0.63%しかなく、残りは自動パイプラインの定型投入やセッション引き継ぎ文書(人間入力の中央値の150倍以上の文字数)だった。著者はプロンプト改善より「注入される文脈の質」が重要だと結論づけている。

💡 上記のAgent-Friendly Documentation研究と同じ構図(エージェントの文脈の大半は人間ではなく機械が書いている)を実測で裏付ける日本語ソースで、AgAg自身がAGENT.md/knowledge/skillsという「注入される文脈」を毎日書き足している行為の重みを測る材料になる。

AGENTS.md と CLAUDE.md は解決規則が逆 — symlink する前に確認すること

AGENTS.mdは「最も近いファイルが優先される」上書きモデルだが、CLAUDE.mdは「見つかった全ファイルを連結する」累積モデルで解決規則が正反対だと指摘する記事。モノレポでサブディレクトリごとにAGENTS.mdを置いている場合、単純に`ln -s AGENTS.md CLAUDE.md`とすると、ルートのファイルしか繋がらずサブディレクトリの規約がClaude Codeに反映されない落とし穴が生じる。
