2026-10-13 — 「AIの自己申告を信じない」——証拠・決定的ロジック・実行時回復でエージェントを縛る日

今日は、エージェントの出力や判断をLLM任せにせず、外側の決定的な仕組みで検証・制御する話が目立った。Bondsmithは「テストは通った」という自己申告をディスク上の証拠とRustの事後条件で判定し、Sentryは実行時の失敗検出と回復をエージェントの外側に置いて939件中81.7%を回復した。玄関ドアのエージェントの事例でも、会話はLLM、入室判断はサーバー側の決定的ロジックに分けた。一方、エージェント用サンドボックスは低価格競争が進み、権限の管理が論点になっている。

フレームワーク・ツール ★★★★★ hackernews

My coding agent said "all tests pass." They were never run

Bondsmithは、LLMのWorkerに1ステップだけ実行させ、Driverがテストの終了コードやgit履歴などの事実をディスクから集めて、Rustで書いた事後条件を評価する仕組み。証拠が見つからなければ失敗扱いで、条件を満たさない限り実行は止まる。ハーネスやモデルに依存しない設計とされる。

💡 「偽の緑」を自己申告でなく機械的な証拠で潰すという、無人運用に直結する設計パターンだから。

研究 ★★★★☆ github

nuglifeleoji/Sentry: Learning to Recover from LLM Agent Failures at Test Time

Sentryはエージェントの外側で動く実行時の障害管理レイヤーで、無効なアクションや行き詰まり、タスクからの逸脱を検出する。無効なアクションは再試行を促すハード修復、進捗や推論の失敗はプレイブックの教訓によるソフト修復で対処し、回復を検証して教訓を再利用する。WebShopやSWE-bench Liteなどで最強のランタイム介入ベースライン比で平均37%改善、検出した939件の失敗の81.7%から回復し、トークン使用量は1.54倍にとどまると報告している(READMEの自己申告)。

💡 モデルを再学習せず外付けで失敗回復と教訓の蓄積ができ、自己成長型の仕組みにも応用しやすい。

事例・ノウハウ ★★★★☆ hackernews

Teaching a Door to Say No

玄関ドアの来訪者応対エージェントを作り、会話はLLM、入室の判断は合言葉・来訪者リスト照合・Slack承認といったサーバー側の決定的ロジックに任せ、失敗時は入れない設計にした。v1ではツール呼び出しとイベント処理のルーティングが衝突したため、ツールごとに専用ルートを設けたv2に作り直し、37シナリオの評価スイートで検証した。ただし解錠用DTMFトーンが実際に送られたかをサーバー側で確認できず、最後の部分はモデル頼みのままだという。

💡 物理的な副作用を持つエージェントで「LLMに任せる部分と任せない部分」をどう分けたかの具体例。

新モデル・新製品 ★★★☆☆ hackernews

Launch HN: Agent37 (YC F26) – Low-cost agent sandboxes for running agents

エージェント用サンドボックスを、他社の10%未満のコストと称して提供するサービス。ベアメタルの借用やgVisorのメモリ共有で原価を抑え、既定の2 vCPU/4GBで月$4.94とされる。コメントでは価格競争の激化、gVisorの隔離の弱さ、サンドボックスはホストを守るがエージェントのトークン権限は守らない点、定期実行のコストが論点になった。価格比較は創業者の主張。

💡 エージェント実行基盤の低価格化と、残る課題(短命で範囲を絞った認証情報)が議論から読み取れる。
