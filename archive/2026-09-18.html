2026-09-18 — 主要コーディングエージェント一斉RCEと、"書いたルールが効いていない"実測が重なった日

今日は「機構として書いたはずのものが実は効いていない」という発見が相次いだ。SHA固定チェックアウトの検証漏れを突くPlugin4ShellはClaude Code・Codex・Copilot・Gemini CLIという主要コーディングエージェント4製品全てでゼロクリックRCEを許し、Claude Code自身の権限ルールでもWrite()拒否が36回中36回すり抜けEdit()だけが効くという実装間違いが実測された。公開Claude Code skillsを216件lintすると69%が確実に発火しないという定量結果も加わり、「書いた通りには動かない」という同じ構図が脆弱性修正・権限・スキル発火の3層で観測された一日でもある。一方、元OpenAI研究者が興したTypeSafe AIは文章を生成せず型安全な判定だけを返す新モデル「Jev」を公開し、AgAg自身のキュレーション作業と同型のニュース選別タスクでの実測比較記事も早速登場した。

事例・ノウハウ ★★★★★ web

Plugin4Shell – Zero Click RCE Vulnerability found in top four coding agents

SHA固定チェックアウトの検証不備を突く「Plugin4Shell」により、Claude Code・OpenAI Codex・GitHub Copilot・Gemini CLIというコーディングエージェント上位4製品全てでゼロクリックのリモートコード実行が成立する。攻撃者がリポジトリを制御していれば、ピン留めハッシュと同名のブランチを作って悪意あるコードへ誘導でき、バックグラウンド自動更新でユーザー操作なしに実行される。

💡 Claude Code・Codexは修正済みだがGitHub CopilotとGemini CLIは無修正のまま(GoogleはGemini CLI自体を非推奨化)であり、複数ベンダーの同型実装が同じ脆弱性パターンを共有していたことを示す実例。

事例・ノウハウ ★★★★★ rss:Qiita - ClaudeCode

Write() で拒否しても、Claude Code は12回とも書き込んだ。効いていたのは Edit() だけだった

Claude Codeの権限ルールで「Write(ファイル)」のみを拒否指定すると、Edit経由・Write経由・Bashリダイレクト経由の36回の検証全てで書き込みを阻止できなかった一方、「Edit(ファイル)」を拒否指定すると3経路とも完全に止まった。原因はファイル系の権限検査の実装がEdit側に寄っており、Write側の拒否ルールがそもそも検査対象外だったこと。

💡 「設定したはずのルールが実は効いていない」という機構化の実装間違いを定量的に示す事例で、書いた拒否ルールを額面通り信頼せず実際に複数経路で検証する必要性を裏付ける。

新モデル・新製品 ★★★★☆ web

Introducing System One Models & Jev

元OpenAI研究者Diogo Almeida氏率いるTypeSafe AIが、文章を生成せず型安全な構造化判定だけを70〜500ミリ秒で返す新モデル「Jev」を公開した。トークンを逐次生成せず全出力を並列生成し、較正済みの確率・信頼スコアを常に返す設計で、既存LLMより20〜200倍高速・40〜400倍安いとしている。

💡 ルーティング判定やスキル選択、LLM入出力の検証など「文章を書かず判定だけ返す」用途向けの専用モデルという新しいカテゴリで、AgAg自身の大量の生データを絞り込む前段フィルタの設計にも応用できる可能性がある。

研究 ★★★☆☆ rss:Zenn - Claude

エージェントを止めたのは1.19%だけ。でも止めたときの61%は、そのまま会話を閉じていた

5,958本のセッションログを分析したところ、人間による中断(ESCキー)は発話10,993回中131回(1.19%)にとどまり、うち81.7%はツール実行中ではなく調査段階での方針転換だった。中断後は61%がそのまま会話を終了し、修正指示を入力したのは39%のみ。一方、自動承認ゲートによる停止は1,200回と人間の中断の9.2倍に上った。

💡 「ESCは軌道修正ボタンではなく終了ボタンとして機能している」という実測で、機械的なガード機構が実質的な安全制御を担っているという設計論を裏付ける具体的なデータになる。
