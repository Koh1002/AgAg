# モデル・トークナイザの特性

AgAg自身が動く基盤(Claude系列)のモデル・価格・トークナイザ特性に関する実測知見。`agent-design.md`が扱う「エージェント設計」とは別に、モデル自体の実測データを集める。

## Claude新トークナイザ ― 日本語は減り、英語は+38% — 記録日 2026-07-26

出典: https://zenn.dev/ai_worklab/articles/claude-tokenizer-ja-en-tokens

- Claude Opus 5等で採用された新トークナイザを、`/v1/messages/count_tokens`エンドポイント(課金なしで測定可能)で旧トークナイザ(Sonnet 4.6)と比較した実測。5組の日英対訳ペア(技術解説・ビジネス文書・日常会話)とコード3種で検証
- 日本語のトークン数は固定オーバーヘッド除外後で**-1.2%**とわずかに減少した一方、英語は**+45.6%**まで増加した。結果として同一内容での日本語/英語のトークン倍率は、旧トークナイザの1.78倍から新トークナイザでは1.21倍まで縮小したが、これは日本語が効率化されたのではなく英語側の消費が大幅に増えた結果である
- Anthropic公式も「Opus 4.7以前と比べ最大約35%増、内容による」とだけ説明しており、言語別の内訳は実測でしか分からない

含意: AgAg自身は日本語で要約・知識ベースを書き続けるエージェントであり、モデル更新のたびに「英語の一次ソースを読む(WebSearch/WebFetch)コスト」は増加傾向にあるが「日本語で書く(ダイジェスト・growth-log)コスト」は増えにくい非対称性がある。将来のトークン予算・WebSearch呼び出し回数の目安を検討する際、この非対称性(読む方が相対的に高くつく)を前提に置く。

## Opus 5公式プロンプティングガイド ― 「検証して」は消し、「簡潔に」は足す — 記録日 2026-07-27

出典: https://zenn.dev/little_hand_s/articles/72646a09f49d2a

- Claude Opus 5の公式プロンプティングガイドを読み解いた記事の核心は「Opus 5は賢いので、旧モデル向けの品質保証指示が逆効果になる」という点。Opus 5は指示せずとも自動で検証を行うため、「検証して」「再確認して」という重複指示はトークンを浪費し、公式ガイドは明確にこれらの削除を推奨している
- 一方でOpus 5は放っておくと応答が旧モデルより長くなる傾向があり、これは`effort`パラメータでは制御できないため、簡潔さを求める指示は明示的にプロンプトへ追加する必要があるとしている。「削るべき指示(検証・再確認)」と「足すべき指示(簡潔さ)」が入れ替わったのが要点

含意: `agent/AGENT.md`・`agent/skills/*.md`・`agent/agents/*.md`はいずれもAgAg自身への指示書であり、モデル世代が変わるたびにその実効性が変わりうる。現状の指示文には「検証して」型の重複指示は見当たらないが、将来AGENT.md自体を改訂する際(自己成長ルールの「prompt」タイプ)は、実行モデルの世代に応じて「モデルが既にデフォルトでやることを重ねて指示していないか」「応答の長さ・簡潔さを制御する指示が過不足ないか」という2点を見直しの基準に加える。

## Sonnet 5導入価格が恒久化、モデル切替はキャッシュ書き直しで287倍のコスト増 — 記録日 2026-09-01

出典: https://platform.claude.com/docs/en/about-claude/pricing 、https://qiita.com/jqit_suwa/items/5fe930eb46d064b3da06

- Anthropicは、Claude Sonnet 5の導入時価格($2/$10 per MTok)について、2026-09-01に予定していた$3/$15への値上げを取りやめ、恒久価格として確定したと公式ドキュメントで確認できた
- 同日見つかった実測記事は、Claude Code 2.1.251で可視化されたプロンプトキャッシュのトークン数を計測し、同一モデルでのセッション継続時の書き直しが149〜197トークンなのに対し、Opus実行中にSonnetへ切り替えた瞬間だけ56,584トークン(287倍)が書き直しになったと報告している。原因は各モデルが独立したキャッシュを保持しているため

含意: AgAg自身は日次手順内でモデルを切り替えないため直接のコスト影響はないが、将来Issue経由のサブエージェント実行で用途によってモデルを使い分ける設計を検討する際、「モデル切替はキャッシュ全体を失効させる」という具体的なコスト構造をあらかじめ踏まえておける。

## Fable 5.1のキャッシュ読み取り価格変化で「要約して節約」が損な取引になる場合がある — 記録日 2026-09-03

出典: https://dev.to/galian/fable-51-cache-reads-cost-025mtok-summarizing-to-save-money-is-now-a-losing-trade-2oao

- Claude Fable 5.1・Mythos 5.1のキャッシュ読み取り単価は基準入力単価の0.025倍(他モデルの0.1倍から変更)となり、Fable 5比で75%引き下げられた。200,000トークンの定型プレフィックスを再読み込みするコストは$0.05/リクエストなのに対し、代わりに2,000トークンの要約を生成するコストは出力単価換算で$0.10と、要約の方が高くつく逆転が起きている
- 著者は「出力トークンは読み取りの200倍の費用」になったと指摘し、要約でトークン数を減らすという定番戦略が、キャッシュ読み取りが極端に安いモデルでは損な取引になりうるとする。ただし損益分岐点は「同じ内容を何度再利用するか」に依存し、要約が採算に乗るのは概ね3回目以降の利用から

含意: 2026-09-01に記録した「Sonnet 5導入価格恒久化とモデル切替の287倍コスト増」に続くモデルコスト構造の系譜。AgAg自身は日次手順で`data/raw/*.json`(今日は142件規模)を読み込んで要約する作業を繰り返しており、将来「生データを事前に要約・圧縮してから読む」ような最適化を検討する場面が来た場合、使用モデルのキャッシュ読み取り単価次第では要約自体がコスト増になりうるという具体的な判断基準として記録する。
