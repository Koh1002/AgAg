2026-10-25 — エージェントの実行基盤と監視の穴、そして「サブエージェントを畳む」指針

GoogleがエージェントごとにmicroVMを割り当てるAgent Compute Engineと拡張ガバナンスを発表した(ACEはプレビュー予定)。一方METRはOpenAIの社内エージェント監視を3週間のパイロットで調べ、圧縮イベントの未監視など複数の抜けを報告した。Anthropicはサブエージェントを評価付きで段階的に単一ループへ畳む手順を示した。個人実測では、テスト提供の効果は仕様がテストにしかない場合に限られ、蓋閉じのMacやCLAUDE.mdの字数上限など運用上の落とし穴も測られた。

Introducing Agent Compute Engine and expanded agent governance

GoogleがAgent Compute Engine(エージェントごとにmicroVMと短命のIDを割り当て、待機中はスナップショットで停止・再開)を発表した。OSSのAgent Substrate on GKEは提供中、ACE自体は今後数か月でプレビュー。Agent Gateway/Registry/Identityなどのガバナンスも拡張される。

💡 権限や秘密をエージェントの外側で強制する基盤側設計が、クラウド事業者の標準機能になりつつあることを示す(10倍の密度や20万エージェントでの数値はGoogle自身の主張)。

事例・ノウハウ ★★★★★ hackernews

Building agents: When to fold subagents into your main agent loop

Anthropicのガイド。コンテキスト肥大や並列の使い捨て文脈が要る場合にサブエージェントを残し、それ以外は単一ループへ畳むことを勧める。手順は、約10件の評価を先に用意し、サブエージェントをツール化して基準を取り、1つずつスキルとツールへ移して、タスク単位の入れ替わりも見る。

💡 AgAgの`agent/agents/`の増やし方にそのまま使える判断基準(ベンダー自身のガイドであり、2倍高速になった事例は顧客の自己報告)。

事例・ノウハウ ★★★★☆ rss:Zenn - Claude

Claude Code にテストを渡しても差はゼロだった。作者の「最重要のコツ」を 72 回試してわかった効く条件

Sonnetで小さなPython課題12件×2条件×3回=72試行を実施。仕様がプロンプトにある11件では差がなく(隠しテスト690ケースで失敗0)、仕様がテストにしかない1件だけ失敗率が74.5%から7.8%に下がった。テスト無しの条件では検証実行の約半数が権限設定で止まった。

💡 「テストを渡す」効果が仕様の置き場所に依存することを示す実測。ただし1モデル・小課題・仕様がテストのみの課題は1件で、示唆にとどまる。

議論・意見 ★★★★☆ rss:Zenn - Claude

蓋を閉じても Claude Code は動いている：macOS の DarkWake が一晩で週間上限を削る仕組み

蓋を閉じたMacBookで、ストリーミング中のセッションがDarkWakeのたびに切れ、会話全体が再送される仕組みを解説。2件のGitHub Issueの報告では、蓋閉じ6.5時間で81リクエスト中29件完了、週間使用量が20%から56%に増えた。課金への影響は利用者側からは不明で、対策は停止してから閉じる等。

💡 長時間エージェントの再送コストが見えない形で積み上がる例。数値は他者のIssue報告の引用で、記事の筆者は関連アプリの宣伝もしている。

事例・ノウハウ ★★★☆☆ rss:Zenn - Claude

Claude Codeのサブフォルダの CLAUDE.md が先頭だけになる境目を測ったら、200Kは4万字、1Mは15万字でした

Claude Code 2.1.310・Sonnet 5.5・Windowsで、サブフォルダのCLAUDE.mdが全文読み込まれる上限を測定。200Kコンテキストは40,000字、1Mは約15万字で切れ、数えるのはバイトでなく字数だった。各条件1回の観測で、版やOSが違えば変わりうる。

💡 指示書が長いと末尾の規則が静かに落ちる可能性があり、AgAgのAGENT.md運用にも関わる(切れた後はRead注記で続きを読めるかはモデル次第)。
