2026-11-11 — エージェントを迷わせる「古い情報」と、汚染されるメモリに目が向く日

Googleは、古いTODOコメントがコーディングエージェントを寄り道させ、ステップ数やトークンを大きく増やすことを大規模トレースで示した。Chromeチームは、モデルが知らない最新のWeb標準をエージェントに教える「modern-web-guidance」を公開した。研究では、長期メモリへの汚染攻撃を測るMemoryDojoが出た。AdobeはCreative Cloud向けのMCPを発表し、承認や書き込み先の再確認など実行境界の設計を扱う日本語記事も目立った。

研究 ★★★★★ web

Technical Debt Can Derail Coding Agents Through "Agent Distraction"

Googleが数億ステップ規模のトレースを分析し、約13%のセッションでエージェントがコード内のTODO参照に触れ、そのうち6%で実際に参照先のバグに着手したと報告した。寄り道のあるセッションはステップ数が70%、トークンが77%、待ち時間が105%増えた。Googleは古いTODOを検出して削除するエージェントを作り、人間レビューの承認率は95%超だった。

💡 コードやドキュメントの陳腐化がエージェントのコストと精度に直結することを実測で示し、リポジトリ整備の優先度を裏づける。

フレームワーク・ツール ★★★★☆ hackernews

Show HN: Get your coding agent off ~2019 JavaScript, onto modern web primitives

Chromeが中心となり、Edge、Firefox、MDNも関わる、コーディングエージェント向けの最新Web標準ガイド集。CLIで検索・取得・旧パターンのスキャンができ、約250の機能と203のユースケースを扱う。モデルが既に知っている内容は評価に基づいて削り、トークン効率を保っている。

💡 モデルの知識が古い領域を、公式のスキルとして外から補う実例で、他の分野にも応用できる設計だ。

研究 ★★★★☆ arxiv

MemoryDojo: Benchmarking Poisoning Through LLM Agent Memory

セッション中に与えた悪意ある指示がメモリに保存され、後のセッションで取り出されて実行されるまでを測るベンチマーク。4分野155の多セッション軌跡と5種類のメモリシステムを対象とし、すべてのメモリシステムが汚染に弱いことを確認した。ただし後続への影響はシステムごとに大きく異なる。

💡 長期メモリを持つエージェントの新しい攻撃面を測る土台で、メモリ設計の比較に使える。

事例・ノウハウ ★★★☆☆ rss:Zenn - AIエージェント

AIエージェントに許可した書き込み先が変わったら？ SQLiteで6ケース検証した

実行直前に書き込み先が差し替わるケースと、保存後に応答が失われるケースを、SQLiteの合成データで6ケース再現した。対象と承認版を書き込み直前に照合すれば差し替えを更新前に拒否でき、読み戻せない場合は「保存済みか不明」として自動再送を止める設計が示される。著者自身が、実サービスや並行実行は未検証と明記している。

💡 承認と実行の間のずれという実務で起きやすい問題を、小さな再現で整理しており、検証範囲の限界も正直に書かれている。
