2026-10-31 — エージェントに判断を委ねる危うさと、推論強度・分割設計の見直し

Anthropicの実験で、専門家が分析判断の86%でエージェントの傾向に従ったと報告された。推論強度は高いほど良いわけではなく、失敗時だけ段階的に上げる戦略が有望とする研究も出た。個人の実測では、サブエージェント分割より単一ループが有利な場面や、Claude CodeのPreToolUseフックで危険なgitコマンドを機械的に止める手法が示された。DoorDashのCEOは、AIエージェント経由の注文が合計で数百件にとどまると述べた。

研究 ★★★★★ hackernews

AI agents shape experts' judgment calls

因果推論の経験がある専門分析者50名(AI使用者)に、Claude Opus 4.8で協同組合プログラムの拡大・廃止を分析させた実験。エージェントの傾向をコイン投げで決めて伝えなかったところ、4つの分析判断への追従率は合計86%だった。事後調査では52%が最終推奨を「エージェントより自分のもの」と評価した。

💡 Anthropic自身の研究で、1課題・1分野・1モデルに限られ傾向も意図的に強めた条件だが、「人間が確認するから安全」という前提が崩れうることを具体的な数値で示している。

研究 ★★★★☆ github

What Effort Level Should I Choose? On the Economics of Reasoning Effort in LLM Agents

8モデル・4ベンチマーク(AIME 2026、GPQA Diamond、Terminal-Bench 2.1、SWE-Bench Proの一部)で推論強度ごとの成否を測った研究。高い強度は低い強度の上位互換ではなく、易しいタスクでは最高レベルのコストが最低レベルの最大42倍になる。最低レベルから始め、検証で失敗したときだけ上げる戦略が、固定の最高レベル以上の結果になったとされる。

💡 リポジトリのREADMEの記述に基づく(論文arXiv:2610.34491の本文は未確認、個別の正答率もページには載っていない)が、推論強度を固定せず失敗時に上げる運用の根拠になる。

事例・ノウハウ ★★★★☆ rss:Zenn - AIエージェント

AIエージェントの「役割別サブエージェント分割」vs「単一ループ統合＋段階的スキル開示」を実機サンドボックスでA/B検証

請求精算パイプラインの6つの埋め込みバグを直す課題で、4ロール分割(3回の要約ハンドオフ)と単一ループ統合を比較した記事。どちらも独立採点20ケースを通過し、単一ループは累計入力トークン約67%減・概算コスト約55%減だった。分割側では要約の切り詰めで仕様が1つ脱落し、手戻りが1回発生した。

💡 各モード1回の実行・単一モデル・単一タスクで、分割とスキル開示方式の効果は分離できていない。一般化はできないが、直列で密結合な作業ほど要約ハンドオフが情報を落とす危険の実例になる。

事例・ノウハウ ★★★★☆ rss:Qiita - AIエージェント

Claude Code の PreToolUse フックで git add -A や reset --hard を機械的に止める(誤検知の避け方つき)

CLAUDE.mdに書くだけでは守られない禁止事項を、PreToolUseフックで機械的に止める記事。標準入力のJSONからコマンドを読み、正規表現に一致すれば終了コード2で理由と代替手順を返す。引用符内やヒアドキュメントを空にして誤検知を減らすが、`;`でつないだ別コマンドの引数を拾う誤検知は残ると筆者が書いている。

💡 個人の運用記録(Windowsは未確認)だが、文章のルールより仕組みで止める方が確実という方針を実装レベルで示している。

研究 ★★★☆☆ arxiv

Prefix Executability: Evaluating Tool-Using Agents Beyond Final Success

ツール呼び出し列のすべての接頭辞が、スキーマ・状態の前提・データ依存のもとで実行可能かを測る評価プロトコル。BFCL-v3、ToolSandbox、τ³-benchで、最終成功だけの順位と接頭辞レベルの順位が食い違うと報告している。要旨のみ確認し、具体的な数値は要旨に無かった。

💡 最終成功だけで評価しない視点は、サブエージェントの出力検証など自分の運用にも使える。実行前の計画チェックで実行可能な接頭辞の生存率が改善するとされる(要旨のみ確認)。
