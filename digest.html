新モデル・新製品 ★★★★★ web

Make long-running agents faster with message threads

Messages APIに`thread`パラメータを加え、長時間エージェントで会話全体を毎ターン再送せず、新しいメッセージと前回のレスポンスIDだけを送れるようにする機能。スレッドは暗号化してメモリ上に保持され、最後のリクエストから5分で失効する。トークン使用量は変わらず、短縮されるのは最初のトークンまでの時間(TTFT)。パブリックベータとして提供中。

💡 Anthropic自身の数値で、50万〜100万トークンの要求ではClaude CodeのTTFT中央値が約35%短縮(同機能は既定で有効)。コスト削減ではなく遅延削減である点に注意。

AIエージェントを並列にするとGitが詰まる理由:OpenAIのPandoと同時push 5.5万回の実験

エージェントを並列に動かしたときにgitが詰まる原因は、リポジトリの大きさではなく同じrefへの同時書き込みだと、3つの実験で示した記事。各自のブランチへのpushは32人でもrejected 0回、全員がmainへpushすると平均3,755回rejectedになった。Codex CLI 4体の実験では、作業ツリー共有だと他者の変更が混入し、worktree分離ではCHANGELOGが15回中9回衝突した。

💡 個人の実験で、pushは1台のマシン内のスクリプトによる計測、エージェント実験は小規模リポジトリ・各5回のみ。Pandoの数値は筆者が検証していない。AgAg自身の並走設計(日付ごとの別ファイル)の裏付けとして応用できる。

「該当なし」と「判定器が落ちた」が同じ終了コード1だった ─ 拒否Hookが黙って通していた話

個人開発サービスの拒否Hookで、判定スクリプトの『該当なし』とimport失敗が同じ終了コード1のため、止めるべきコマンドが黙って通っていた。対策として、正常時は常に終了コード0でfound/noneを出力し、『終了コード0かつnone』のときだけ通し、未知の値は拒否した。matcherがツール名の列挙だったため後から追加されたツールで起動しない問題も直した。

When 200 OK Is Not an Answer: Silent Fetch Failures in Agentic Web Content Acquisition

Webエージェントや回答エンジンが、HTTP 200を取得成功とみなしてよいかを調べた論文。3日間で1,507サイトの10,307 URLを取得し、静的取得の200のうち自動ラベル上20.9%は本文が無い(アプリの殻、ボット確認、エラーページなど)と報告した。200を成功扱いすると、検証できる引用の割合を12.2ポイント過大に見積もる。簡易な判定の組み合わせで、使えない応答の86%を誤検知約5%で検出できたという。
